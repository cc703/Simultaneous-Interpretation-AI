# 最终演示路径

目标：让评审看到题目二的完整闭环，而不是只看到页面控件。

## 0. 启动

正式录屏建议同时启动前端和本地 AI Gateway：

```bash
cd interpreter
npm run dev:server
```

另开一个终端：

```bash
cd interpreter
npm run dev -- --host 127.0.0.1
```

打开 `http://127.0.0.1:5173`。右上角显示 `AI 引擎在线 · dashscope` 时，说明前端已经识别到后端。

录屏前先跑：

```bash
npm run smoke:final
```

## 1. 先跑 File 主线

1. 输入源切到 `文件`。
2. 源语言选择 `自动检测`，目标语言选择 `中文`。
3. 点击 `加载样本`，加载内置英文样本。
4. 点击 `开始同传`。
5. 观察状态和字幕：`英文音频 -> ASR 转写 -> 中文字幕`。
6. 讲解：评审看到的是一段英文音频进入系统，经过转写后生成目标语言字幕，再进入修正、术语和导出流程。
7. 如果 ASR Key 可用，就展示真实 ASR 转写结果；如果没有 ASR Key，系统只使用明确标注的样本转写文本，不伪装真实 ASR。

## 2. 展示修正闭环

1. 点击一条字幕。
2. 在修正区修改目标语言译文。
3. 点击 `保存修正`。
4. 讲解：字幕标记为人工修正，修正记忆会记录用户确认译文，后续真实翻译 prompt 会参考它。

## 3. 展示术语重译

1. 打开 `设置 -> 术语`。
2. 添加或确认当前场景术语。
3. 选择包含该术语的字幕。
4. 点击 `术语重译`。
5. 讲解：术语命中和重译结果体现专业场景的一致性控制。

## 4. 补充展示 Demo 稳定模式

1. 输入源切到 `演示`。
2. 选择 `Product Launch` 或 `Technical Talk` 场景。
3. 点击 `开始同传`。
4. 讲解：Demo 模式用于无 Key 情况下稳定证明完整产品闭环，便于录屏和备用演示。

## 5. 展示 Live 稳定性设计

1. 打开本地直播源 `http://127.0.0.1:5173/live-room.html`，开始播放测试视频。
2. 回到主应用，输入源切到 `直播`。
3. 讲解 Live 路径：`选择直播源 -> 捕获浏览器音频 -> 分片 ASR -> 目标语言字幕 -> 修正导出`。
4. 点击 `选择直播音频`。
5. 选择带英文音频的网页直播、社交平台直播、媒体直播或会议标签页，并确认共享音频。
6. 如果未配置 ASR Key，讲解状态会停在 `Audio captured · ASR not configured`：系统已捕获直播音频和波形，但不会生成假字幕。
7. 如果 ASR Key 可用，讲解 Live 统计：`Queued`、`Done`、`Silent`、`Dup`、`Latency`。系统会跳过过短/静音片段，并对重复转写做去重，避免字幕刷屏。

## 6. 导出

1. 点击 `导出` 下载 SRT。
2. 点击 `复制` 复制双语文本，或在剪贴板不可用时自动降级下载文本。
3. 确认导出内容包含源语言、目标语言、时间戳和修正后的字幕。

## 必须说明的边界

- Demo 模式用于稳定证明完整产品闭环。
- File / Live 真实 ASR 依赖后端 provider、Key、网络和供应商能力。
- Live 面向真实网页/社交/媒体直播和线上会议；用户必须主动授权浏览器共享音频。
- Live 是几秒级准实时分片，不承诺零延迟。
- 当前前端单文件建议 25MB 内；DashScope inline 音频建议 10MB 内。
