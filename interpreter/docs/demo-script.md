# Demo 录屏讲解脚本

本脚本用于比赛提交视频，目标是清楚展示题目二“AI 同声传译助手”的核心闭环：外语音频流输入、实时中文字幕、语音输出、翻译修正和导出。

建议时长：3 到 5 分钟。

## 录制前准备

1. 启动项目：

```bash
cd interpreter
npm install
npm run dev
```

2. 打开 `http://localhost:5173`。
3. 保持输入源为 `Demo`，不需要 API Key 也能完成稳定演示。
4. 可选：如果要展示真实流式翻译，在左侧 Provider 面板填写 OpenAI-compatible API Key。

## 讲解顺序

### 1. 说明选题和目标

“本项目选择题目二：AI 同声传译助手。目标是把外语音频流实时转换为中文字幕，并提供语音播报、人工修正、术语增强和字幕导出能力。”

画面操作：展示顶部标题、输入源、Provider、术语表和字幕工作区。

### 2. 展示实时字幕流

“我先用 Demo 模式展示稳定评审闭环。点击 Start Interpreting 后，英文发言会按时间轴逐句进入字幕区，而不是一次性显示全部内容。”

画面操作：

1. 点击 `Start Interpreting`。
2. 等待字幕逐条出现。
3. 指出底部大字幕和右下统计栏会同步变化。

### 3. 展示中文语音输出

“打开 Chinese voice output 后，系统会使用浏览器中文语音播报新生成的中文字幕，满足题目要求中的字幕或语音输出。”

画面操作：

1. 勾选 `Chinese voice output`。
2. 让下一句 Demo 字幕出现并播放。
3. 可打开 `Settings` 展示语速调节。

### 4. 展示翻译修正能力

“同传场景中译文可能需要人工快速修正。这里我选择一条字幕，直接在 Correction Desk 修改中文，然后保存。”

画面操作：

1. 点击一条字幕卡片。
2. 在 `Correction Desk` 修改中文译文。
3. 点击 `Save correction`。
4. 展示字幕卡片标记为用户修正，Corrections 计数增加。

### 5. 展示术语表和重译

“专业会议里术语一致性很重要。系统支持添加术语，并对选中字幕进行术语重译。”

画面操作：

1. 在术语表添加 `pitch deck` -> `融资演示文稿`。
2. 选择包含该词的字幕。
3. 点击 `Retranslate with glossary`。
4. 展示术语命中标签和译文变化。

### 6. 展示文件模式

“文件模式用于模拟上传会议录音或视频后的同传字幕流。当前 MVP 使用文件播放进度驱动内置转写流，稳定展示文件播放、字幕生成、修正和导出闭环。”

画面操作：

1. 切换到 `File`。
2. 上传一个音频或视频文件。
3. 点击 `Start Interpreting`。
4. 展示文件名、进度条、波形和字幕输出。

边界说明：“这里不是任意音频文件的真实 ASR 识别，真实文件音频分片识别会通过后续 ASR Adapter 接入。”

### 7. 展示直播捕获入口

“Live 模式实现了浏览器标签页或屏幕音频捕获入口，可以看到捕获来源和 Web Audio 波形。由于 Web Speech API 不能直接消费系统音频流，直播音频的真实 ASR 也预留给 ASR Adapter。”

画面操作：

1. 切换到 `Live`。
2. 点击 `Choose tab audio`。
3. 选择一个标签页或屏幕。
4. 展示捕获状态和 `Stop live capture`。

### 8. 展示导出

“最后，系统支持把当前字幕结果导出为 SRT，也可以复制双语文本，方便课后整理或提交会议纪要。”

画面操作：

1. 点击 `Export` 下载 SRT。
2. 点击 `Copy` 复制双语文本。

### 9. 总结开发过程

“开发过程按单功能 PR 推进：状态管理、UI、STT、流式翻译、修正闭环、Demo、导出、文件模式、直播捕获、设置面板、波形、TTS 和最终演示材料。主分支始终保持可运行，每一步都经过构建验证。”

## 必须避免的说法

- 不要说“已经支持任意文件音频真实识别”。
- 不要说“已经支持任意直播音频真实识别”。
- 可以说“已经实现文件和直播入口，并预留 ASR Adapter 扩展”。
- 可以说“Demo 模式用于保证评审时稳定展示题目要求的完整产品闭环”。
